1. 全向运动模式示意图
这张图要表达的核心：
三舵轮底盘可以实现不同方向的全向运动。

怎么画：

整张图分成 3 个小图，并排放
每个小图都画一个底盘俯视图：
一个长方形表示车体
3 个圆点/小圆轮表示三个舵轮
前面中间 1 个
后面左右各 1 个
在车体中间画一个小坐标系：
X 轴向前
Y 轴向左
三个小图分别画：

纯前进

在车体前方画一个向前的大箭头
下面标：Vx > 0, Vy = 0, ω = 0
纯横移

在车体左侧画一个向左的大箭头
下面标：Vx = 0, Vy > 0, ω = 0
原地旋转

在车体外侧画一个逆时针圆弧箭头
下面标：Vx = 0, Vy = 0, ω > 0
这一页图的重点：

让老师一眼看出“全向运动”是什么意思
不需要太复杂，不需要公式
2. 三舵轮结构与坐标系示意图
这张图要表达的核心：
你后面做运动学建模时，车体坐标系和三个舵轮位置是怎么定义的。

怎么画：

单独画一个较大的底盘俯视图
中间是一个矩形车体
三个舵轮还是三角布局：
前舵轮
左后舵轮
右后舵轮
在车体中心画原点 O
从原点画坐标轴：
X 向前
Y 向左
图上要标注：

三个轮子的名称
三个轮子的相对位置
车体中心坐标原点
Vx、Vy
一个 ω 的旋转方向箭头
如果你想更专业一点，还可以加：

从中心到三个轮子的虚线
在轮子下面标它们的位置参数 (xi, yi)
这一页图的重点：

支撑你“建立坐标系、推导运动学模型”的内容
这是中期答辩里比较重要的一张图
3. 系统总体方案框图
这张图要表达的核心：
你的课题整体技术路线是什么，系统是怎么串起来的。

怎么画： 从左到右画 5 到 6 个矩形模块，中间用箭头连接。

建议画成这样：

手柄输入 / 上层速度指令
→ 目标速度生成
→ 速度平滑处理
→ 三舵轮逆运动学解算
→ 执行器命令下发
→ 状态反馈

每个框里具体写：

输入层

手柄输入
上层速度指令
目标生成

生成 Vx / Vy / ω
控制层

速度平滑处理
逆运动学解算
执行层

舵角命令
轮速命令下发
反馈层

编码器反馈
速度/角度状态更新
如果你想画闭环：

从“反馈层”再用一个回箭头回到前面
标“闭环反馈更新”
这一页图的重点：

体现你的课题不是零散功能，而是完整系统
中期答辩里特别适合用来讲“目前已经做到了哪一层”
4. 控制程序流程图
这张图要表达的核心：
你的 STM32 程序执行逻辑是什么。

怎么画： 从上到下画流程框，用箭头串起来。

建议画 6 到 7 步：

系统初始化
接收输入
生成底盘目标速度
速度平滑处理
三舵轮逆运动学解算
执行器命令下发
状态反馈与循环执行
每一步框里可以写：

系统初始化 / 读取配置参数
接收手柄按键或上层速度指令
生成 Vx、Vy、ω
三角形加减速轨迹平滑
求解舵角和轮速命令
发送控制量到驱动器
更新角度、速度和运行状态
这一页图的重点：

支撑你“控制程序设计”这一页
让老师知道你已经开始进入实现阶段，而不只是停留在理论
5. 仿真验证流程图
如果你还想多画一张，这张也很适合中期。

这张图要表达的核心：
仿真平台是怎么服务于你的课题的。

怎么画： 从左到右画：

cmd_vel 指令
→ 速度转换节点
→ 三舵轮控制器
→ Gazebo 底盘模型
→ 记录 bag 数据
→ 绘制曲线分析

每个框可以写：

输入速度指令
cmd_vel_to_three_steer
舵角/轮速控制器
Gazebo 模型运行
数据记录
曲线分析
这一页图的重点：

强调仿真是验证手段
不是让老师觉得你只是在做仿真
6. 实物测试展示页应该怎么排
这个不是画图，是排版图。

这页要表达的核心：
你已经有阶段性实物验证。

怎么做：

一页分成 3 或 4 个区域
每个区域放一个运动模式：
前进
后退
横移
旋转
每个区域里放：

视频截图 2~3 张
下方写一句话：
前进测试：底盘可沿车体前向稳定运动
横移测试：底盘可实现侧向平移
旋转测试：底盘可完成原地转向
这页重点：

这是中期答辩里最有说服力的页之一
比花哨图更重要
中期答辩最值得准备的图，一共就这几类
如果你时间不多，就优先做这 5 张：

全向运动模式示意图
三舵轮结构与坐标系示意图
系统总体方案框图
控制程序流程图
实物测试结果展示页
哪些图要简洁，哪些图可以复杂一点
要简洁的
全向运动模式示意图
结构与坐标系示意图
这两张是“概念图”，越简单越好。

可以稍微复杂的
系统总体方案框图
控制程序流程图
因为它们承担的是“讲思路”的功能。

最重要但不需要画的
实物测试结果页
这个靠你的视频截图，不靠手绘。
